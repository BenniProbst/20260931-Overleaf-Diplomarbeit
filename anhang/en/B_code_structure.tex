\chapter{Code Structure}\label{app:code}

This appendix documents the source-code structure of the four repositories from Section~\ref{sec:repos}
verifiably at directory level (two to three levels deep). Authoritative for each repository is the branch
\texttt{development}: for the two code repositories in the commit that the super-repository carries as
submodule pointer (gitlink\footnote{A submodule is a Git repository embedded in a superordinate
repository; \texttt{.gitmodules} declares \texttt{path} and \texttt{url} per submodule, optionally
\texttt{branch} and \texttt{update}. The gitlink is the commit of the submodule recorded in the
superordinate repository~\cite{git2026gitmodules}.}), for the super-repository its own state and
for the manuscript repository the commit from which the CI builds the PDF\@: \texttt{comdare-cache-engine}
\texttt{eb69abc1}, \texttt{comdare-prt-art} \texttt{b539d6ee},
\texttt{probst-\allowbreak{}Diplomarbeit-\allowbreak{}cache-\allowbreak{}engine} \texttt{d989e008} and
\texttt{20260931-\allowbreak{}overleaf-\allowbreak{}diplomarbeit} \texttt{d32cc492}. Build artefacts
(\texttt{build*/}), IDE directories and LaTeX build artefacts are hidden; the vendored third-party code
under \texttt{ext/} and the preliminary documents of the thesis appear as collective entries. All paths
named exist in the named state; paths are given relative to the respective repository root. The
licence basis of each repository (\texttt{LICENSE}, \texttt{NOTICE}, \texttt{LICENSES/},
\texttt{REUSE.toml}\footnote{REUSE is a specification of the Free Software Foundation Europe for
machine-readable licence and copyright information: the licence texts reside under \texttt{LICENSES/}
with the SPDX identifier as file name, and \texttt{REUSE.toml} maps files to their
licences~\cite{fsfe2024reuse}.}) is part of the structure; the licence statement of the thesis itself is
made in the front matter.

\section*{comdare-cache-engine --- building-block library, planner and builder}

The repository follows the Pitchfork layout\footnote{Convention for the directory structure of native
C/C++ projects (Pike, \emph{cxx-pflR1}; specification in the repository \texttt{vector-of-bool/pitchfork}):
\texttt{apps/} for programs, \texttt{libs/} for libraries, besides \texttt{tools/}, \texttt{tests/},
\texttt{docs/} and \texttt{external/} as named root directories~\cite{pike2018pitchfork}.}:
\texttt{apps/} contains the executable programs, \texttt{libs/} the libraries, \texttt{libs/common}
the cross-cutting code and \texttt{libs/traeger} the division into the four carrier stages; the vendored
third-party code lies collected under \texttt{ext/} and is not expanded here. A GNU build path precedes
the CMake build: \texttt{configure.sh} and a static \texttt{Makefile} with the GNU standard
targets\footnote{\texttt{all}, \texttt{install}, \texttt{check}, \texttt{installcheck},
\texttt{uninstall}, \texttt{clean}, \texttt{distclean}, \texttt{mostlyclean} and
\texttt{maintainer-clean} according to the GNU Coding Standards, section \emph{Standard Targets for
Users}~\cite{gnu2026standards}; the test target there is called \texttt{check}, not \texttt{test}.} hand
over to the building CMake script.

The axes reside in three realms (axis homes; Appendix~\ref{app:glossary}), one per category: \texttt{organ\_\allowbreak{}axes/} (22 directories: the 18
main composition axes, \texttt{organ\_\allowbreak{}meta\_\allowbreak{}meta/} as well as \texttt{cacheline/}, \texttt{simd/} and
\texttt{telemetry\_\allowbreak{}axis/}), \texttt{system\_\allowbreak{}axes/} (\texttt{target\_\allowbreak{}isa}, \texttt{operating\_\allowbreak{}system} and
\texttt{external\_\allowbreak{}utils} together with their sub-axes as well as \texttt{compiler}, \texttt{scheduling} and
\texttt{extension\_\allowbreak{}hardware}; sub-axes include \texttt{optimization\_\allowbreak{}level}, \texttt{compiler\_\allowbreak{}atomic}
and \texttt{simd}) and \texttt{mess\_\allowbreak{}axes/} (measurement tooling registry of the three measurement levels
\texttt{wallclock}, \texttt{macro} and \texttt{micro}). Each realm owns a generated registry XML
as a machine-readable image of its contents:
\texttt{algorithm\_\allowbreak{}profiles/\allowbreak{}cache\_\allowbreak{}engine\_\allowbreak{}axis\_\allowbreak{}registry.xml},
\texttt{include/\allowbreak{}cache\_\allowbreak{}engine/\allowbreak{}measurement/\allowbreak{}system\_\allowbreak{}axis\_\allowbreak{}registry.xml}
and \texttt{measurement\_\allowbreak{}axis\_\allowbreak{}registry.xml}, generated by \texttt{tools/\allowbreak{}axis\_\allowbreak{}registry\_\allowbreak{}gen},
\texttt{system\_\allowbreak{}axis\_\allowbreak{}registry\_\allowbreak{}gen} and \texttt{measurement\_\allowbreak{}axis\_\allowbreak{}registry\_\allowbreak{}gen} via
compile-time reflection. The canonical order of the 18 composition axes is \texttt{search\_\allowbreak{}algo},
\texttt{cache\_\allowbreak{}traversal}, \texttt{mapping}, \texttt{path\_\allowbreak{}compression}, \texttt{node\_\allowbreak{}type},
\texttt{memory\_\allowbreak{}layout}, \texttt{allocator}, \texttt{prefetch}, \texttt{concurrency},
\texttt{serialization}, \texttt{value\_\allowbreak{}handle}, \texttt{index\_\allowbreak{}organization}, \texttt{io\_\allowbreak{}dispatch},
\texttt{migration\_\allowbreak{}policy}, \texttt{filter}, \texttt{queuing\_\allowbreak{}q1}, \texttt{queuing\_\allowbreak{}q2} and
\texttt{persistence\_\allowbreak{}target}. The carrier stages \texttt{planner}, \texttt{ceb}, \texttt{tier} and
\texttt{hybrid} are laid out as CMake targets under \texttt{libs/traeger/}; their substance resides in
\texttt{libs/cache\_\allowbreak{}engine/}: \texttt{profile\_\allowbreak{}facade/planner/} for the planner, \texttt{builder/} for the
builder, \texttt{anatomy/} and \texttt{organ\_\allowbreak{}axes/} for the tier substance, \texttt{hybrid/} for the
hybrid stage. The file identity of the building blocks is secured by the overlay source set
(\texttt{builder/\allowbreak{}overlay\_\allowbreak{}source\_\allowbreak{}set.hpp}, member~[7] of the tier fingerprint, hash via
\texttt{tools/\allowbreak{}overlay\_\allowbreak{}source\_\allowbreak{}hash\_\allowbreak{}gen}) and the version lock
\texttt{tools/\allowbreak{}axis\_\allowbreak{}version\_\allowbreak{}lock/\allowbreak{}axis\_\allowbreak{}version.lock}, which the CI gate
\texttt{contract:axis-version-lock} checks.

\section*{comdare-prt-art --- candidate under test}

The candidate under test is organized as a header library\footnote{Header-only: a library whose definitions reside
entirely in header files and are compiled upon inclusion; there is no separately compiled library
file.} under \texttt{prt\_art/\allowbreak{}include/\allowbreak{}prt\_art/}; each building block
resides in its own thematic subdirectory (14), \texttt{prt\_art/src/} is an empty
implementation directory (header-only; the entire library code resides under \texttt{include/}). The cache engine loads it as a plugin: \texttt{comdare\_pruefling.cmake} registers
the code path via \texttt{COMDARE\_CE\_PRUEFLINGE}, the generated \texttt{prt\_art\_axis\_registry.xml} is
the registry path for the planner (\texttt{COMDARE\_PRT\_ART\_DIR}); a cross-check in the candidate contract
of the cache engine reports it when only one of the two paths is set, and aborts the configuration
when both point to different locations (Section~\ref{sec:prtart-impl}). In the stamp the candidate under test carries
its axes under its own namespace (prefix \texttt{prt-art.}).

\section*{probst-Diplomarbeit-cache-engine --- super-repository}

The super-repository bundles the measurement driver, the experiment configurations, the nine-stage
evaluation pipeline (\texttt{01} to \texttt{09}), CI checks and the embedding of the three other
repositories as submodules~\cite{git2026gitmodules}. Under \texttt{Code/\allowbreak{}external/} reside three
entries: the two code repositories and the manuscript repository as the static location of the LaTeX
attachment generated from the measurement, next to the rest of the source code, a location that also
covers operation without a network. The same manuscript repository is additionally embedded as the
build path \texttt{thesis/\allowbreak{}diplomarbeit}, in which the CI builds the PDF\@; \texttt{.gitmodules}
thus lists four submodules.

\section*{20260931-overleaf-diplomarbeit --- manuscript repository}

The manuscript repository contains the LaTeX sources of both language versions (switch
\texttt{\textbackslash{}thesislang} in \texttt{diplomarbeit.tex}), the generator output of the measurement under
\texttt{anhang/\allowbreak{}\{de,en\}/\allowbreak{}tabellen/} and its own CI with the jobs
\texttt{lint:secrets}, \texttt{lint:latex} and \texttt{thesis:pdf}. The measurement CI of the super-repository
deposits the generator output by commit in this repository and triggers the PDF build; this
write-back channel is the reason why the manuscript is its own versioned repository
(Section~\ref{sec:repos}). In the super-repository it is embedded twice: as the build path
\texttt{thesis/\allowbreak{}diplomarbeit} and as the static location
\texttt{Code/\allowbreak{}external/\allowbreak{}20260931-\allowbreak{}overleaf-\allowbreak{}diplomarbeit}. The
assignment sheet resides as its own chapter under \texttt{aufgabenstellung/}; the licence basis is CC BY 4.0
(\texttt{LICENSES/\allowbreak{}CC-BY-4.0.txt})~\cite{cc2013by40}, the licence statement is in the front matter.
