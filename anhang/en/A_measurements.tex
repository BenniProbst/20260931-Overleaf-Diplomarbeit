This appendix documents the measurement series and evaluation artefacts of the measurement chain
(Section~\ref{sec:mess-chain}). Table~\ref{tab:measurements:v5_pipeline_demo} lists, per
pre-configured living-being permutation, the metrics of the 16-column schema: the operation count
(\texttt{op\_count}), the representative p50 latency in nanoseconds --- carried in the schema under
the legacy column name \texttt{total\_cycles} and headed \enquote{cycles} in the table; these are
not clock cycles\footnote{\texttt{total\_cycles}: the field of the snapshot schema holds the
representative latency of the measurement in nanoseconds (the merged p50 value), not counted
processor cycles; the column name is a legacy of the first schema version; the column is therefore
headed \enquote{cycles} and denotes the p50 latency in nanoseconds.} --- as well as the columns of
the cache misses L1--L3, which are not collected in this series (\texttt{pmc\_available} $= 0$) and
are therefore tabulated as 0: they are to be read as explicitly coded non-observation (principle
of explicitly coded non-observation, Section~\ref{sec:axis-triad}), not as a measured zero; an
output of these cells as n/a is not implemented. With the switch
\texttt{COMDARE\_ENABLE\_PMC} set (build option, default off so that the unit tests build without
hardware access; the CI sets it in the PMC paths), the measurement chain collects L1D, last-level,
dTLB and branch misses generically via
\texttt{perf\_event\_open}\footnote{\texttt{perf\_event\_open}(2): the Linux system call that opens a
hardware or software counter as a file descriptor; generic events are mapped by the kernel per
microarchitecture, model-specific ones require the raw encoding of the event
(\texttt{PERF\_TYPE\_RAW}: event number and mask as the hardware counts
them).}~\cite{demelo2010perf} as well as L2 demand misses and fills from the cache of a foreign
CCX\footnote{CCX (core complex): a core complex with its own L3 cache; demand fills from the cache
of another CCX are the coherence observable of the core PMU, a literal invalidation counter does
not exist in the event set.} model-bound via the RAW event catalogue --- cross-checked by
measurement for the AMD Zen~5 microarchitecture (CPUID family
26)~\cite{linux_perf_amdzen5,weaver2008counters}; models without a catalogue entry (all Intel
models) carry n/a (limitation~1 in Section~\ref{sec:measurements:limitations};
Section~\ref{sec:eval-counters}). Figure~\ref{fig:measurements:v5_pipeline_demo} compares the same
metric graphically; its axis label \enquote{Cycles} follows the legacy column name. The series
documented here are smoke proofs of the complete chain run with axis variation; they do not replace
the mandatory measurement series A--C (Section~\ref{sec:eval-available},
Table~\ref{tab:stage-series}), whose complete runs are not available (n/a) because the full build
has not been carried out.

and~\ref{tab:measurements:cartesian_smoke43}) originate from the in-process path

(Section~\ref{sec:eval-available}). All other artefacts of this appendix stem from \emph{one} smoke

The metrics of this appendix are distributed over the three measurement levels of the
measurement-tooling main axis --- wallclock (w), macro (ma) and micro (mi) in exactly this order
(Section~\ref{sec:measurement-system}): \texttt{ns\_per\_op} $=$
\texttt{total\_ns}/\texttt{timed\_ops} is the host wall-clock of the measurement across the load
framework (w); \texttt{op\_<kind>\_p50} and \texttt{op\_<kind>\_p99} are the latencies of the family
interface operations \texttt{insert}, \texttt{lookup}, \texttt{erase}, \texttt{scan} and
\texttt{rmw} of the tier binary (ma); \texttt{seg\_<axis>\_ns} and \texttt{stat\_<axis>\_<field>}
are the per-axis times and observer counters across the axis interfaces (mi); the PMC columns
belong to the micro instrumentation (mi). This appendix does not redefine the levels, it assigns
them: Table~\ref{tab:measurements:artefakt-ebenen} names, per artefact, the metric, its level and
the data basis that the present corpus contains. In every section the design statement (what a
representation delivers) is separated from the corpus statement (what the present run contains).

\section[head={Cartesian Smoke Series (43 Permutations)}]{Cartesian Smoke Series (43 Permutations, DLL Measurement)}

The following measurement series arose from the complete chain run: 43 built permutation DLLs in
two sub-blocks --- 27 cartesian combinations SIMD $\times$ memory layout $\times$ allocator
(\texttt{avx2}, \texttt{scalar}, \texttt{sse4} $\times$ \texttt{aos}, \texttt{hybrid}, \texttt{soa}
$\times$ \texttt{jemalloc}, \texttt{mimalloc}, \texttt{std}) and 16 combinations over four
two-valued quantities (node width \texttt{compact}/\texttt{wide}, path compression
\texttt{lazy}/\texttt{none}, internal search \texttt{binary}/\texttt{linear}, telemetry
\texttt{leaf\_only}/\texttt{sampling}; $2^4$) --- were measured at the probe dock, persisted as
binary measurement records, converted via pipeline stage~03 into the 16-column schema and embedded
automatically. The variant names are the build matrix of this series; in the axis model of the
code, SIMD is a system axis (option \texttt{avx2} of the registry of the system axes), memory
layout and allocator are organ axes (\texttt{memory\_layout}, \texttt{allocator}), and telemetry is
not a \texttt{binary\_id} axis (limitation~2 in Table~\ref{tab:le:limitierung}); the remaining
names do not coincide in name with registry building blocks and are not equated with them. The
series thus varies seven quantities; the complete measurement series varies all 18 composition
axes, plus the optional organ meta-meta axis \texttt{disk\_io} without a \texttt{binary\_id} share.
Table~\ref{tab:measurements:cartesian_smoke43} and Figure~\ref{fig:measurements:cartesian_smoke43}
show the results; the HW columns stand at 0 = not collected, and the axis label \enquote{Cycles} of
the figure follows the legacy column name (see above).

\section{Reference-Relative Evaluation}\label{sec:measurements:reference}

The following representations relate all measured values to \emph{one} reference. That reference is
a measured axis value of the corpus itself (default \texttt{search\_algo}/\texttt{linear\_scan})
and expressly \emph{not} an external library baseline: a measured \texttt{std::map} performance
series does not exist, because every \texttt{std::map} in the corpus is the conformance oracle of
the probe dock and thus a correctness, not a performance data point. If the reference axis value
does not occur in a measurement series, the representations of this section carry the note of the
missing reference or its substitute text; in the present corpus \texttt{linear\_scan} is not
measured alongside, all ratio representations are therefore without a denominator (n/a).

\subsection{Ratio Matrices}\label{sec:measurements:ratio-matrices}

Per interface function, one matrix shows the quotient of the measured median and the reference
median. The diverging colour scale is centred on equality (ratio~1), so that advantage and
disadvantage relative to the reference are distinguishable without comparing numbers. In the
analysis role this matrix supersedes the heatmap of Section~\ref{sec:measurements:surfaces}; the raw
heatmap remains alongside it as the raw-value view. In the present corpus neither the ratio matrix
nor the heatmap carries data (reference not measured; surface below $2{\times}2$). Where ratios
are aggregated, this is done geometrically, never as an arithmetic mean of
quotients\footnote{The arithmetic mean of normalized ratios depends on the choice of reference and
can reverse the ranking; the geometric mean, by contrast, is
reference-invariant~\cite{fleming1986statistics}.} --- this also holds for the normalized bars of
the next subsection.
